# OpenWrite 风格合约拆解与提炼

- 上游：<https://github.com/LiPu-jpg/Openwrite>
- 检查日期：2026-08-09
- 上游许可证：Apache-2.0
- 边界：本仓库新增的 JavaScript、提示词、表格和测试均为独立实现；未复制上游代码、文案、界面或来源作品文本。

## 机制拆解

OpenWrite 把通用技法、来源文本提取结果和当前项目正典分成三层；来源分析会区分可复用风格信号与作品绑定信息，经过明确采纳后才进入写作上下文。它还将写稿、审稿和修订读取同一份有界上下文，而不是临时让每一阶段各自猜测风格。

## 本技能原有基础

本技能已有作者意图与当前焦点、预算化 context pack、章节记忆、事实账本、伏笔证据回收、事务回滚和冷读门禁。继续搬运 OpenWrite 的 Studio、数据库、模型适配器或全维度审稿产品会破坏“安装即用、文件优先”的边界，未采纳。

## 本轮提炼

新增一个与项目证据链绑定的轻量风格层：

| OpenWrite 思路 | 本技能落点 | 验收 |
|---|---|---|
| 来源信号与作品专属内容隔离 | `evidence/derivations/style-signals.md` 只登记抽象、可复用信号及其证据路径 | 编译时拒绝空证据、未知维度、重复 ID 与未知范围 |
| 明确采纳后才进入项目 | `scripts/style-contract.js` 只编译采纳/启用行，输出 `state/style-contract.json` 与来源哈希 | 单元测试覆盖状态、范围、警告和输出 |
| 同一风格包贯穿生产 | `chapter-transaction begin` 重编译并冻结哈希；context pack、初稿、修订、冷读读取该合约 | 事务集成测试断言合约与关键上下文 |
| 审稿以证据确认风格是否兑现 | `style_signal_checks` 对每条到期信号提供原文证据；失败让章节继续修订 | 冷读验证测试覆盖遗漏、失败、错误放行 |

## Fanqie 定位

该层不以模仿某一部作品为目标。它把“开篇先给动作和阻力”“对话承载冲突信息”“移动端段落节奏”等可迁移结果，与榜单/拆书/课堂/读者反馈的证据绑定，再让当前书的冷读报告验证是否真的出现在正文里。这样适合番茄项目的连续生产，也可回溯每条风格约束来自何处。
