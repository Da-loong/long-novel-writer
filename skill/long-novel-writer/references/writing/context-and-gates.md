# 长篇上下文与章节门禁

## 原则

把长期记忆拆为可追溯的三层，而不是把整个项目塞进提示词：

| 层级 | 内容 | 更新频率 | 用途 |
|---|---|---:|---|
| Hot | 当前状态、人物状态、时间线、未解钩子、最近章节 | 每章 | 决定下一场能发生什么 |
| Warm | 读者契约、文体、故事圣经、人物关系、当前大纲 | 设定或结构变化时 | 保持承诺和方向 |
| Cold | 更早正文与归档事件 | 原文落盘后不改 | 按人物、道具、地点或伏笔精确召回 |

摘要是缓存，不是事实源。任何召回项必须保留源文件路径、纳入字符数、是否截断和相关度分数。发生冲突时回读原章节。

## 写作前：生成上下文包

```powershell
node scripts/context-pack.js <项目目录> --chapter 42 --query "人物名 道具名 HOOK-7" --recent 3 --retrieve 3 --budget 40000
```

默认写入 `state/context-pack.md`。选择顺序：

1. 固定纳入 Hot 状态和 Warm 核心文件。
2. 纳入目标章之前最近三章。
3. 用显式查询词对更早章节做确定性词项评分，选择前三章。
4. 超出预算时保留文件首尾并标明截断；不伪造中段摘要。

查询词应来自本章章纲：POV、出场人物、地点、道具、能力、未解钩子 ID。没有查询词时不假装做语义检索，只纳入固定层与最近章。

## 写作前门

```powershell
node scripts/chapter-gate.js <项目目录> --stage pre --chapter 42
```

阻断条件：

- 章号不是 `updated_through + 1`；
- 项目存在缺章、重复 ID 或状态滞后；
- 上下文包缺失、目标章不匹配或生成后项目状态发生变化；
- 章纲缺少该章，或 POV、目标、阻力、转折、得失、信息、情绪、钩子任一字段为空；
- 故事圣经或读者契约仍保留初始化提示。

门禁通过只证明输入准备完整，不替代创作判断。

## 写作后门

逐章落盘后，先更新：

1. `state/project-state.json.updated_through`；
2. `state/current-state.md` 的 `updated_through`；
3. 人物状态、时间线、未解钩子和伏笔台账；
4. QA 报告中的证据与复评。

再运行：

```powershell
node scripts/chapter-gate.js <项目目录> --stage post --chapter 42 --min-chars 1800 --max-chars 3500
```

后门检查章文件、目标字数、占位文本、重复段落、缺章和状态提交。`--min-chars` 与可选的 `--max-chars` 按用户约定或平台章长设置，不以统一默认值覆盖明确要求。

## 中断恢复

跨会话继续时按此顺序：

1. 运行 `validate-project.js`，以机器状态和文件序列确定最后确认章。
2. 若最新章存在但状态未提交，把它视为未完成事务；回读该章并补台账，禁止直接跳到下一章。
3. 从新章章纲提取查询词，重建上下文包，不复用目标章号不同的旧缓存。
4. 运行写作前门；通过后才起草。
5. 落盘、提交状态、运行写作后门；失败则修复同一章，不继续批量生成。

这形成“准备—写作—提交—验证”的逐章事务边界。批量写 1–3 章时也逐章完成整个边界，避免批末一次性补状态造成漂移。
