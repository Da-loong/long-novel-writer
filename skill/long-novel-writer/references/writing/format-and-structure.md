# 格式规范

## 核心目标
保持章节正文、项目说明和状态数据之间的结构边界。

## 执行步骤
1. 章节文件使用统一的四位章号和标题。
2. 正文只保留章标题、正文和固定场景分隔。
3. 段间使用单空行。
4. 大纲与状态使用结构化表格或列表。
5. 不在正文插入检查分数、占位符和工具日志。

## 输出格式
`ch-0001-title.md`

## 验收清单
- 文件名可稳定排序。
- 正文复制发布时无需二次清理。
- 项目数据不会混入叙事文本。

## 番茄移动端正文契约

这是发布稿格式，不是大纲格式：

- 文件名固定为 `manuscript/ch-XXXX-title.md`；正文只保留一个章节标题和故事正文。
- 段落之间只留一个空行；正文不出现 Markdown 表格、列表、代码围栏、提纲小标题或工具日志。
- 单段中文字符默认不超过 260；超过阈值先拆成动作、反应、对白、结果四类短段。句子超过 100 字时优先拆句。
- 对白独立成段并使用统一中文引号；对白必须完成索取、拒绝、试探、威胁、交易或关系位移中的至少一项。
- 每章至少出现目标、阻力、主动选择、可见结果和章尾新问题；连续以“然后/接着/随后”起段，或连续只罗列时间顺序，判为流水账风险。
- 格式检查只做硬门禁；动作密度、对白缺失和因果稀薄同时写入警告，交给冷读与章节复核判断。

执行：

```powershell
node scripts/format-gate.js <章节或目录> --json
```

`chapter-gate.js --stage post` 和 `autopilot-runner.js` 会自动调用该检查。失败稿保留在 Agent 运行记录中，不进入下一章。
