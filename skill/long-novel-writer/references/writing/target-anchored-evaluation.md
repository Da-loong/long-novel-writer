# 目标锚点评审

长篇自动生产不只检查“写得像不像”，还要检查目标是否在正文中兑现。每个目标都必须写成可核验的锚点，避免只用模型总分判断。

## 锚点结构

```json
{
  "id": "C001-HOOK",
  "level": "chapter",
  "target": "第1章让读者看见主角必须在停电中救出被困同事",
  "deadline": 1,
  "evidence": [
    {"path": "manuscript/ch-0001-标题.md", "quote": "原文中可检索的兑现片段"}
  ],
  "status": "fulfilled"
}
```

## 四层目标

| 层级 | 必填目标 | 典型证据 |
|---|---|---|
| 书级 | 书名、简介、题材承诺 | 前 3 章和卷一回报 |
| 卷级 | 本卷主问题、升级方向、卷尾回报 | 卷中转折与卷尾兑现 |
| 章级 | 本章目标、阻力、选择、代价、钩子 | 章节动作、结果、章尾变化 |
| 读者级 | 看懂、紧张/爽/惊、愿意继续 | 读者报告中的复述、评分与下一章意愿 |

## 自动判定

- `fulfilled`：至少一个正文证据片段，且片段确实改变了目标状态。
- `deferred`：延期有明确截止章和读者可见的新问题。
- `broken`：到截止章仍无兑现，或证据只是一段作者解释。
- `unknown`：没有可检索证据；进入返工队列，不自动算通过。

## 评审顺序

1. 先检查书级承诺，再检查卷级回报。
2. 再逐章核对事件图、章拍和正文证据。
3. 最后检查读者目标：能否用一句话复述主角目标、眼前阻力和本章得失。
4. `broken` 或 `unknown` 不能通过；先修章拍/场景，再做句子润色。

## 自动盲评 JSON 最低字段

`autopilot.js pilot-pass` 的 evidence 文件除分数外，还应包含：

- `target_anchors`：至少 3 个书级/章级目标；
- 每个锚点的 `path`、`quote`、`status`；
- 每个 reader report 的 `summary`、`confusions`、`continue_next`；
- `critical_failures` 与对应的证据片段。

分数与锚点冲突时，以证据链为准；高分不能覆盖 `broken`。
