# 读者体验指标

`reader-metrics.js` 只做可重复的预警，不把数字伪装成文学裁决。

## 每章检查

```powershell
node scripts/reader-metrics.js <章节或目录>
```

指标包括：

- `opening_action_delay_chars`：前面多少字才出现明确动作或问题；
- `dialogue_ratio`：对白中文字符占比；
- `exposition.longest`：连续长解释段数量；
- `ending_chars`：章尾长度与形状提示；
- `warnings`：需要人工冷读的证据。

## 默认提示线

- 前 300 个中文字符仍没有动作/问题：检查开头成交；
- 连续 2 段以上、每段至少 120 字且没有对白：检查说明书段落；
- 对白占比超过 40%：检查是否用聊天凑字数；战斗/悬疑章可收紧到 25–35%；
- 章尾长段没有动作、问题或明确状态变化：检查追更钩子。

这些线来自平台向写作项目的工程化经验，只能作为预警。真正的 `reader_pass` 仍需要目标读者冷读、复述测试和“是否愿意点下一章”。
